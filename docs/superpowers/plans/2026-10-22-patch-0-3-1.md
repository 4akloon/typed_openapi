# typed_openapi 0.3.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Four fixes found while generating the Zeely core-api client (NestJS, OpenAPI 3.0): event-name words, inline-enum names that depend on an unrelated site, a manifest `inputs` hash over the whole spec, and dead operation overrides.

**Architecture:** Each fix is local: `DartNames` gets an event-name word rule; the `Declarer` stops merging inline enums across locations; `ClientWriter` hashes the IR instead of the raw files; the IR builder reports overrides of operations the filter left out.

**Spec:** the owner's task statement (below, "Requirements") plus the rulings. No separate design document; the code was read in the investigation summarised under "Findings".

## Requirements (the owner's, verbatim in substance)

Fixes only, each with a regression test and a CHANGELOG line under `### Output changes` where generated code changes. Do not publish or tag. Done when package tests and `dart analyze --fatal-infos` pass, generated docs (enums/unions/event streams) show the new names, CHANGELOGs list the output changes, versions are 0.3.1. Report which generated names change.

1. **Event union names.** `USER_INBOX_UNREAD_COUNT_UPDATED` on `sendUserInboxUnreadCountUpdates` generates `SendUserInboxUnreadCountUpdatesEventUSERINBOXUNREADCOUNTUPDATED`, `...EventUSERINBOXUNREADCOUNTUPDATEDData`, file `..._event_userinboxunreadcountupdated_data.dart`. Must be `SendUserInboxUnreadCountUpdatesEventUserInboxUnreadCountUpdated`, file `..._event_user_inbox_unread_count_updated_data.dart`. Same for every name derived from an event.
2. **Shared inline enum.** Two inline enums with the same values are one type named after the first site (a `type` query parameter typed `ResolveUgcVideoScriptDurationRequestDtoTypeKnown`, a request body of another operation); a value added to one copy renames the other. Name an inline enum after its own site; deduplicate only identical enums that already have the same site-derived name, or not at all. Keep the lock/diff report accurate for the rename.
3. **Manifest `inputs`** hashes the whole spec, so with `include` filters an unrelated backend change rewrites the manifest of a committed client. Hash what generation depends on.
4. **Dead overrides.** An override of an operation that `include`/`exclude` leaves out is applied silently and generates nothing. Report it like a missing target (TOA804 class warning).

## Findings (code read before planning; paths under `packages/`)

- `DartNames.pascal` (`typed_openapi_core/lib/src/ir/names.dart:153`) splits on `[^A-Za-z0-9]+` and then camel/acronym boundaries, and `_capitalize` keeps the tail of each word, so `USER_INBOX` -> `USERINBOX` by design (`UserDTO` stays `UserDTO`). It must not change for other names. Event names reach identifiers in `ir/event_union_names.dart:57`, `ir/override_events.dart:~70-77` (variant name and `NameHint(prefix, 'Event${words}Data')`), `ir/event_union_reader.dart:~146-147` (same hint). The file name comes from the type name through `ModelLibrary.snake` (`typed_openapi/lib/src/emit/model_library.dart:87`), which lowercases `DartNames.words`, so fixing the type name fixes the file.
- Inline enums: `Declarer.declare` (`ir/declarer.dart:~63-85`) merges inline enums by `EnumDraft.key` (`ir/mapping_state.dart:183`, `MappingState.inlineEnums`:195, registered in `_register`:~110-127); components are never merged. The merged copy points at the first-created declaration, whose `NameHint` came from the first operation that reached the value set. `DeclId` is the schema location (+ `DeclVariant`); the lock/snapshot identity is `NameLock.declarationKey` = the first owner's location, so after the fix each location owns its own entry (a location that was merged has no lock entry and gets a fresh site-derived name; `diff` shows a type added and members typed differently, which is accurate).
- Manifest: `typed_openapi/lib/src/cli/client_writer.dart:~91-115` `_inputsOf` hashes `generator`, the raw bytes of every `check.sources` file, `client.generation.key`, `line_width`, preset and `disabledRules`. `ClientCheck.irJson` already exists. `OutputManifest.render` writes it. No test pins a concrete hash; `generate_command_test.dart:~136` ("the manifest changes with the inputs") appends a comment to the spec and expects a different manifest. `corpus.lock` hashes every file but the manifest, so it is not affected.
- Filter: `OperationSelector.select` (`ir/operation_selector.dart:~22-45`) is called at `ir/ir_builder.dart:43` and drops an operation that is not included, is excluded, or whose override has `exclude`. `IrOverrides` (`ir/ir_context.dart:24-35`) maps resolved entries to locations. TOA804 `overrideTargetNotFound` is in `diagnostics/diagnostic_code.dart:1167`, reported by `overrides/override_target_reporter.dart`. TOA810-TOA819 are free (the 8xx codes in use: 800-809, 820-823, 830-835).

## Rulings (planner; the controller records them in the ledger)

- R1: Event names are split into words with an event-only rule, not by changing `pascal`: a separator-delimited piece with no lowercase letter (`USER`, `UPDATED`, `HTTP`) is lowercased before the word split; mixed-case pieces are untouched (`userInbox`, `UserDTO` unchanged). `DartNames.pascal` and every other name stay byte-identical.
- R2: No inline-enum deduplication across locations at all. The only identical enums that "already have the same site-derived name" are the same location, which already has one `DeclId`. Collisions between sites that derive the same name are resolved by the existing `2`, `3` suffixes.
- R3: `inputs` = sha256 of `jsonEncode({generator, line_width, ir: check.irJson})`. The IR is exactly what the emitters read (filtered operations, reachable components, applied overrides, config effect, lock names); a comment, an unrelated component, an excluded operation or an override of one do not change it. Config reaches it through its effect (naming, types, union, ...), not through the config file's text. Cost if wrong: a setting that changes output without changing the IR; none is known because the emitter's only input is the IR.
- R4: The new code is `TOA810 override-operation-not-generated`, a warning, reported once per operation entry (its parameter, body and response overrides are dead with it), at the override entry in the overrides file. Not reported when the entry's own `exclude: true` is the cause. Schema overrides that no generated operation reaches are not covered in 0.3.1 (a reachability question; noted in the CHANGELOG as a known gap).
- R5: `corpus.lock` and the goldens are regenerated once, in the last task. Earlier tasks update only the goldens and fixtures their own change moves.
- R6: Version 0.3.1 as ordered. The repository's `corpus semver` rule requires a minor raise before 1.0 for a change of generated output (decision 7), so its CI job will not accept 0.3.1; the controller reports this to the owner and does not change the rule.

## Review Focus

- Event names with digits, kebab, dotted, camelCase, a lone caps word, an empty-after-split name (Event<n>, TOA668), two events that differ only by case/separators (collision suffix `2`, TOA551).
- Inline enums: the same enum on a query parameter and a body property; an enum inside a component reached by two operations (one declaration, unchanged); the lock keeping the first owner's name and giving the other site a fresh one (TOA570/TOA571 behaviour); `knownValues` collapse (TOA455) and unions of enums still work; names of enums in `@input`/`@patch` variants.
- Manifest: same output, different unrelated spec text -> identical manifest; a changed included operation -> different; `include` filter hiding the changed operation -> identical.
- TOA810: operation override with `exclude: true` (no report); override of an operation filtered by `include` and by `exclude` patterns; parameter override under a filtered operation (one report on the operation); an override that does resolve and is generated (no report); `check`, `generate` and baseline fingerprints of the new code.
