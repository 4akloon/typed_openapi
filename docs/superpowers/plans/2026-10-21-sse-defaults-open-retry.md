# Client Defaults and Stream Open Retry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Default `CallOptions` given once per generated client, and retry on transient failures when a stream opens and when it reconnects, so an app deletes its own reopen loops (release 0.3.0 of the four packages).

**Architecture:** `ClientSender(transport, {defaults})` merges the defaults with each call's `CallOptions` once, at the top of `send`/`openEvents`; every later stage reads the merged value. `SseOptions` becomes all-nullable ("unset"), and an internal `SseSettings` applies the built-in defaults after the merge. One classifier (`SseRetry.isTransient`, overridable by `SseOptions.retryWhen`) and one `ReconnectionPlan` per call serve both the opening (new `StreamOpening` collaborator) and the reconnections (`SseReconnector`); `Retry-After` lengthens the delay of one attempt. The generator passes `defaults` down the root and group constructors.

**Tech Stack:** Dart 3.10 (pure Dart, web-safe client: no `dart:io` in `typed_openapi_client/lib`), `package:test`, `fake_async`, the pub workspace of `/CLAUDE.md`.

**Spec:** `docs/superpowers/specs/2026-10-20-sse-defaults-and-open-retry-design.md` (binding). Read it and `CLAUDE.md` first. The owner approved its four "Decisions for the owner" as recommended: B (generated constructors take `defaults`), P1 (the `Future` waits), `retryOpen` unset follows the reconnection policy, `TransportError` kind `other` is final.

- Built-in defaults after merging: `delay` 1 s, `maxDelay` 30 s, `maxAttempts` 5, `jitter` 0; "off" values: `Duration.zero` timeouts, `jitter: 0`, `SseCooldown.none`, `retryOpen: false`.
- `maxAttempts` = retries after a failure: at most 1 + 5 openings; when used up the opening returns the **last** `Failure`, a reconnection ends with `SseDisconnected(cause: last failure)`.

A `DecodeError`/`UndocumentedStatus`/`HttpError` is classified by its status.
- `Retry-After`: delta-seconds or HTTP-date (IMF-fixdate, RFC 850, asctime) against the response `Date` header, else `DateTime.now()`; delay = `max(Retry-After, backoff incl. jitter)`, not capped by `maxDelay`, this attempt only; unparsable, zero or past falls back to the backoff.

## Review Focus

Failure modes the spec implies; each has a test in the owning task (named there).

1. `Retry-After` garbage: empty, `abc`, `-5`, `0`, a 30-digit number, a date in a form no RFC 9110 recipient accepts, a date form with no `Date` header: must fall back to the backoff, never throw, never overflow a `Duration` (T4, T6).
2. The user's `Last-Event-ID` header is sent on every attempt of a retried opening, and the stream's own id replaces it only after an event (T6).
3. `defaults.headers` and `call.headers` with different spellings and a `null` call value; the merged map must neither send both spellings nor resurrect the default (T2).
4. A `retryWhen` that returns `true` for everything never loops on a cancel: `Cancelled` is not classified, and a cancel during a backoff ends the call at once (T6).
5. A default `cancel` signal that is already cancelled: every call without its own signal returns `Cancelled`, a call with its own signal still runs (T2).
