# M12b plan: core split, engine and generator

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split `packages/typed_openapi` into `typed_openapi_core` (the engine: load, repair, check, IR, config, overrides, baseline, snapshot, diff) and `typed_openapi` (emitters, `generate`, CLI), with `typed_openapi_test_support` for the tests both share, and change no generated byte.

**Architecture:** Cut the one engine-to-generator import first (`RealPaths`), then move 243 `lib/` files and 137 test files with a scripted `git mv` and import rewrite, export from the core barrel exactly what `dart analyze` says the generator needs, and carry the tool, CI and docs over in small commits. Every commit builds, passes analysis and tests, and generates the same output.

**Tech Stack:** Dart 3.10 pub workspace, `package:test`, `git mv`, `dart fix`, a few throwaway Python and shell scripts (Appendix, not committed), `typed_openapi_tool` (`corpus check`, `fuzz`).

**Spec:** [2026-10-20-m12b-core-split-design.md](../specs/2026-10-20-m12b-core-split-design.md)

## Global Constraints

- Pure refactor: no behaviour change; generated code byte-identical; `packages/typed_openapi_tool/corpus.lock` is never edited; `corpus check` ends with `40 clients, 38 generated, 27759 files; 0 differences from the lock.`
- Baseline test counts at `main` (92007c1): generator `+1523 ~1`, client `+305`, dio `+54`, tool `+203` (with the SARIF schema in the corpus cache; without it `+201 ~2`).
- Counts after the split: core `+1173`; generator `+352 ~1`; tool `+206` (`+204 ~2` without the schema); client `+305` and dio `+54` unchanged. Core plus generator is 1,525: today's 1,523 and the second `size_limits_test` pair.
- Minimum SDK `>=3.10.0 <4.0.0` in every package. No Flutter.
- No re-export of the core from `typed_openapi` in the final state; the transitional one of Task 4 is gone after Task 5.
- No `src` import across packages (`implementation_imports` is on; `dart analyze packages` must print `No issues found!`).
- CLAUDE.md limits: `lib/` file at most 300 lines, test file 500, method 40, parameters 5, nesting 3. A file already over a limit never grows. Every public member of `lib/` has a doc comment (also in `typed_openapi_test_support`). No `// ignore:` without a reason.
- A refactor never shares a commit with a behaviour change. Commit messages are Conventional Commits, English, each ending with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Formatting: `dart format` of the touched packages changes 0 files on a second run.
- Versions are lockstep: `typed_openapi_core`, `typed_openapi_client`, `typed_openapi`, `typed_openapi_dio` all `0.0.1`; publish order core, client, typed_openapi, dio.
- Dependencies by use: a pubspec lists what its own `lib/` and `test/` import, nothing else.
- Tests never touch the network (`corpus check` fetches specs once; the SARIF schema once with `corpus fetch sarif_schema`).
- English only.

## Review Focus

Failure modes the spec implies that no unit test of a task targets; each says how it is pinned.

1. **One generated byte differs** (an escape, an ordering, a path in a fingerprint or a manifest changes because files moved). Pinned by Task 8: `diff -r` of 186 generated files of the 20 fixture clients and of `typed_openapi.lock` between `main` and the branch, and `corpus check` with 0 differences.
2. **A symbol the generator needs is not exported, or a generator symbol leaks into the core barrel.** Pinned by `dart analyze packages` (undefined names, `implementation_imports`) in Tasks 4 and 5, and by Task 5's check that the generator barrel has exactly 4 `export` lines for the 5 symbols and no core export.
3. **A test is left behind, lost or counted twice in the move.** Pinned by the counts above and by `find packages/typed_openapi_core/test -name '*_test.dart' | wc -l` = 137 and `packages/typed_openapi/test` = 31 (Task 4).
4. **An allowlist entry is lost or invented in the ratchet split** (a unit over its limit is then unlisted and fails, or a stale entry hides a regression). Pinned by both `size_limits_test.dart` passing and by the entry counts in Task 4 step 9 (core 4 files + 21 methods, generator 3 files + 5 methods).
5. **A fixture is read relative to the current directory**, so a test passes only from its own package. Pinned by Task 3 step 6: a program run from an unrelated directory reads `petstore.yaml` through `Fixtures`.

## Conflicts and open questions

Conflicts found while checking the brief against the repository (each has a resolution in the plan):

1. **"No re-export" against a green intermediate commit.** The tool and 12 files import `package:typed_openapi/typed_openapi.dart` for engine symbols, so the commit that moves the engine cannot compile them unless the generator barrel re-exports the core. Resolution: Task 4 adds a marked transitional `export` of the core barrel; Task 5 moves the tool and deletes it. The final state has none.
2. **Method entries: 25 in the brief, 26 in the code** (21 core + 5 generator). All 26 are kept.
3. **`publish.yml` says releases "bump only what changed"; the decision is lockstep.** Task 6 rewrites the comment and adds a test that pins equal versions.
4. **Two barrels cannot both be the home of `RealPaths`.** The generator needs it and it cannot live in `generate/` if `ConfigLoader` (core) uses it. Resolution: Task 1 moves it to `paths/`; the core exports it.
5. **`CLAUDE.md` says the tool "uses the generator's public API only" and temp files go through `test/helpers/temp_dir.dart`.** Both change in Task 7 (the tool uses the core's and the generator's; `TempDir` is in `typed_openapi_test_support`).
6. **`docs/superpowers/HANDOFF.md` is dated 2026-10-13 and does not list M12.** Task 7 adds only the M12b row.
7. **Tool test counts depend on the corpus cache.** `+203` needs the SARIF schema in `packages/typed_openapi_tool/.dart_tool/corpus/specs` (`dart run bin/corpus.dart fetch sarif_schema`, network, once); without it the two SARIF tests skip and the count is `+201 ~2`. A fresh worktree does not have it: copy `.dart_tool/corpus` from the main checkout, or fetch.

### `rewrite_imports.py` (Task 4 step 3)

```python
"""Points the generator's imports of engine code at the core barrel."""
import os
import re

CORE_DIRS = {'baseline', 'check', 'config', 'diagnostics', 'diff', 'ir', 'load',
             'model', 'normalize', 'overrides', 'parse', 'paths', 'resolve',
             'snapshot'}
BARREL = "import 'package:typed_openapi_core/typed_openapi_core.dart';\n"
IMPORT = re.compile(r"^(import|export) '([^']+)'([^;]*);\n", re.M)


def is_core_import(path, text):
    """Whether the import in [path] names a folder that moved to the core."""
    m = re.match(r'package:typed_openapi/src/([a-z_]+)/', text)
    if m:
        return m.group(1) in CORE_DIRS
    if text.startswith(('package:', 'dart:')):
        return False
    target = os.path.normpath(os.path.join(os.path.dirname(path), text))
    marker = 'packages/typed_openapi/lib/src/'
    return (target.startswith(marker)
            and target[len(marker):].split('/')[0] in CORE_DIRS)


for root in ('packages/typed_openapi/lib', 'packages/typed_openapi/test'):
    for d, _, fs in os.walk(root):
        for f in fs:
            if not f.endswith('.dart'):
                continue
            p = os.path.join(d, f)
            src = open(p).read()
            seen = [False]

            def sub(m):
                if m.group(1) != 'import' or not is_core_import(p, m.group(2)):
                    return m.group(0)
                if seen[0]:
                    return ''
                seen[0] = True
                return BARREL
            out = IMPORT.sub(sub, src)
            if out != src:
                open(p, 'w').write(out)
```
