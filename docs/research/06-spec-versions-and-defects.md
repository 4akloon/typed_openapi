# 06. OpenAPI versions, Overlay / JSON Patch and the catalog of defects in generated specifications

> Research date: **2026-10-11**. Concerns requirements R0.1, R0.2, R1.2, R1.4, R2.1–R2.5, R3.1–R3.3, R5.x, R6.x, R8.x, R9.x, R10.x, R11.4, R12.x, R13.1, R14.1, R15.5, R15.6.
> Primary sources: specification texts (markdown sources from the OAI repository, checked against spec.openapis.org), RFCs, framework documentation, GitHub issues/PR/discussions. Numbers in square brackets `[S#]` lead to the "Sources" section.

## Summary

- **Current versions as of 2026-10-11:** OAS **3.0.4** (2024-10-24), **3.1.2** (2025-09-19), **3.2.0** (2025-09-19) and **3.2.1** (2026-09-10, a patch with text clarifications only). 3.3 is in progress; there is no release date. Moonwalk (4.0) has no date and may never be released at all. Overlay: **1.0.0** (2024-10-17), **1.1.0** (2026-01-14, added `copy`), **1.2.0** (2026-09-22, added reusable actions and `$self`) [S1][S2][S3][S20][S21].
- **Specifications generated by frameworks mix dialects.** NestJS before 12.0.0 wrote `nullable` into 3.1 documents and `type: 'null'` into 3.0 documents. FastAPI from 0.134/0.135 puts the OAS 3.2 `itemSchema` field into an `openapi: 3.1.0` document. ASP.NET in 3.0 mode removes `type` from numbers. Therefore the parser must determine the dialect by the content, not only by the `openapi` field (rule `detect-schema-dialect`, SG001–SG003).
- **The main headache is nullability.** In real documents it is written at least six ways: `nullable`, `type: [T, null]`, `anyOf`/`oneOf` with `{type: null}`, `allOf` with one `$ref` plus `nullable`, `type: 'null'` alongside a structure, `enum` with `null`. The normalizer reduces all six to one canonical form.
- **Second by frequency — names.** Here there are noisy names, duplicated ones, unstable `operationId`s, and silent collisions of schemas with the same class names. Springdoc silently takes the first schema of such, so the collision is not visible in the specification itself.
- **Overlay:** an action whose `target` matched no node is, according to the specification, considered **successful**. Therefore R3.2 (a warning on an override of a dead element) must be implemented with our own diagnostic. There is no Overlay implementation for Dart on pub.dev, but the ready-made `json_path` (RFC 9535), `rfc_6901` and `rfc_6902` exist [S27][S28][S29].
- **Catalog:** section C has 48 defects with evidence, about 40 named rules and a code scheme `SG0xx`–`SG8xx`. Section D has recipes for NestJS, FastAPI, Spring and ASP.NET.

**What from 3.2 already occurs in real documents:**
- FastAPI emits `itemSchema` for JSONL and SSE, and `data` is described as `{type: string, contentMediaType: application/json, contentSchema: <Item>}` [S32][S34].
- NestJS allows setting tags with `parent`/`kind`/`summary` via `setOpenAPIVersion('3.2.0')` [S35].
- Swagger UI/Editor have supported 3.2 since April 2026 [S23].

### A.3. What follows from this for the parser architecture

1. **The internal model is a superset of 3.2.** Documents 3.0 and 3.1 are lifted to it, and everything then works with one model. 3.2 has no breaking changes relative to 3.1 [S24], so the superset is safe.
2. **The schema dialect is determined by the content.** The `openapi` header sets only the default value. If a 3.0 document contains a `type` array, `{type: 'null'}`, `const`, `prefixItems` or an `examples` array, the schema is read as 2020-12, and the user gets diagnostic SG001. Conversely: `nullable` in a 3.1 document gives SG002 (see C-16, C-17).
3. **Canonical nullability.** The model keeps `nullable` as a property of a reference to a type: of a field, an array element, a map value. The six input spellings are reduced to it by the `nullable-*` rules (section C).
4. **Unknown JSON Schema keys are not lost.** They are kept as metadata (R6.7). If a key affects the shape of a type (`if`/`then`/`else`, `dependentSchemas`), an info is issued with a suggested override (R2.5).
5. **The patch version is ignored** [S1]: `3.1.0`/`3.1.1`/`3.1.2` are handled the same way, and so are `3.2.0`/`3.2.1`.

## B. Patch and overlay standards (R3.3) and JSON Pointer for diagnostics (R2.2)

### B.1. OpenAPI Overlay Specification

**Structure (1.2.0)** [S3]:

```yaml
overlay: 1.2.0                 # REQUIRED; Overlay version, not OpenAPI
$self: https://example.com/fix.overlay.yaml   # 1.2+, without fragment
info: {title: ..., version: ..., description: ...}  # description appeared in 1.1+
extends: ./openapi.yaml        # optional: target document (since 1.2 — without fragment)
actions:                       # REQUIRED, ≥1, applied IN SEQUENCE
  - target: "$.paths['/users/{id}'].get"   # RFC 9535 JSONPath
    description: ...
    update: {operationId: getUser}         # merge
  - target: "$.paths.*.get.parameters[?@.name == 'dummy']"
    remove: true
  - target: "$.components.schemas['Bar']"
    copy: "$.components.schemas['Foo']"    # 1.1+
  - $ref: '#/components/actions/addErrorResponses'  # 1.2+ reusable action
    target: "$.paths.*.*.responses"
components:                    # 1.2+
  actions:
    addErrorResponses:
      description: ...
      fields: {update: {...}}  # any Action fields except target
```

**Semantics**, per the text of 1.2.0 [S3]:
- Actions are applied in order. Each one acts on the result of the previous one.
- `update`, if `target` is objects: recursive merge. A primitive replaces a primitive, an array is **concatenated** with an array, an object is merged recursively, other combinations are an error. If `target` is arrays: an array value is concatenated, and an object or a primitive is appended to the end. If `target` is primitives: the value is replaced (since 1.1; in 1.0 the target MUST be an object or an array [S20]).
- `remove: true` removes the node from a map or an array. `update` and `copy` are ignored in that case.
- `copy` (1.1+) — a JSONPath to **one** source node. The merge follows the same rules. The pair `update` (create an empty target) + `copy` + `remove` gives a "move", that is, a rename [S3][S25].
- If `target` selects **0 nodes**, "the action succeeds without changing the target document". If there are ≥2 nodes, all of them must be of one kind (objects, arrays or primitives).
- JSONPath MUST be a full implementation of RFC 9535 without the extensions of individual tools. When moving to 1.1 the expressions had to be rewritten: `@['x-oai-traits']` instead of `@.x-oai-traits`, and the `in` operator, which does not exist in the RFC, had to be replaced with a filter [S3][S25].
- YAML comments may be lost.

**Limitations that matter to us:**

| Limitation | Consequence for R3.x | What we do |
|---|---|---|
| 0 matches = silent success | Contradicts R3.2 (an override of a dead element must give a warning) | We count the matches for each action and at 0 we emit **SG802 warning** |
| No `test` or preconditions | It is not visible that the backend has already fixed the defect | After an action we compare the document "before" and "after". If it has not changed — **SG803 info**: "the override can be removed" (R3.2) |
| Arrays are only concatenated | An array (`required`, `enum`) cannot be replaced with one `update` | `remove` of an array element (1.1+ for primitives) + `update` or `remove` of the whole array + `update` of the parent. Our override format (R3.1) has its own "set" operation |
| Map keys cannot be renamed | Renaming a schema through an overlay is awkward | `copy` + `remove` (1.1+). Our override `rename` renames the logical name in the model, not the key in the document |
| Logical entities (operationId, parameter name) cannot be addressed except by a filter | An override such as "operation X" in an overlay is fragile | Our override format addresses logically (R3.1). Overlay is only an alternative input (R3.3) |
| JSONPath strings differ between older libraries | An overlay written for Speakeasy-alpha may not work with us | Strict RFC 9535 + a diagnostic with the error position in the expression |

### B.2. JSON Patch (RFC 6902)

- The document is an array of operations that are executed in order. Each has `op` and `path` (JSON Pointer) [S9 §3–4].
- Operations: `add` (replaces an existing member; `-` at the end of the path means "append to the end of the array"; the parent MUST exist), `remove` (the target MUST exist), `replace` (the target MUST exist), `move` (`from` cannot be a prefix of `path`), `copy`, `test` (a comparison that takes the type into account: `10` ≠ `"10"`) [S9 §4.1–4.6].
- **Atomicity:** if any operation fails, the document is not changed at all ("HTTP PATCH is atomic") [S9 §5]. Media type — `application/json-patch+json`.

**For R3.3:** JSON Patch is more precise than an overlay, because it addresses a specific node and has `test`, that is, a precondition. However:
1. **Atomicity contradicts R3.2.** For example, `remove` of a non-existent path must give a warning, not fail the generation. Therefore the operations are executed one by one in a "soft" mode: a failed operation becomes warning SG801, and the rest are applied. The strict mode is enabled optionally.
2. **Array indexes are fragile** (`/parameters/2`). It is worth warning (info) about patches with numeric indexes in `parameters`/`allOf`/`oneOf` and suggesting logical addressing from our format.
3. **`test` gives R3.2 for free.** If `test` on the "defective" value fails, the defect is already fixed. Then SG803: "the patch is no longer needed".

### B.3. JSON Pointer (RFC 6901) for diagnostics (R2.2)

- Escaping in a reference token: `~` → `~0`, `/` → `~1` [S8 §3].
- **Decoding order:** first `~1` → `/`, then `~0` → `~`, so that `~01` is correctly decoded to `~1` [S8 §4].
- In a URI fragment, characters that the `fragment` rule (RFC 3986) does not allow are percent-encoded [S8 §6]. A reference example from the OAS specification: `#/paths/~12.0~1repositories~1%7Busername%7D/get` [S1 §Link Object]. Here `{` and `}` are encoded as `%7B`/`%7D`.
- `-` as an array index is always an error when evaluated (only for `add` in JSON Patch) [S8 §4].

**Examples for our diagnostics:**

| Location | JSON Pointer (string form) | URI fragment |
|---|---|---|
| Operation `GET /users/{id}` | `/paths/~1users~1{id}/get` | `#/paths/~1users~1%7Bid%7D/get` |
| JSON body schema | `/paths/~1users/post/requestBody/content/application~1json/schema` | `#/paths/~1users/post/requestBody/content/application~1json/schema` |
| Property with `~` in its name | `/components/schemas/A/properties/a~0b` | the same |

**Recommendations:**
1. A diagnostic contains the **string form** of the pointer (stable, readable), as well as the file and `line:col` from the YAML/JSON parser (source map). For references the fragment form is built.
2. The pointer points to the place in the **original** document, not to the normalized result: R2.2 requires explaining what to fix in the source. Therefore the normalizer keeps a source map: which node came from which one.
3. **The key for the baseline (R2.3)** is built as `code + semantic anchor`, not as a "raw" pointer. Array indexes (`/parameters/3`, `/oneOf/1`) change on reordering, so for array elements the anchor is a logical key: a parameter — `name+in`, a variant — the `$ref` target or a hash of the content.
4. For `$ref` between files the format is: `relative/file.yaml#/json/pointer`, where the file path is taken relative to the root of the config (R13.1 — no absolute paths).

### C.3. What cannot be fixed automatically (diagnostic + override only, R2.5)

- The type of a dangling or empty `$ref` (C-2, C-3): the rule sets a JSON value, and the real type can be set only by an override.
- The value type of a dictionary (C-26), `oneOf` without a discriminator (C-45), a discriminator mapping without `const` in the subschemas (C-41), SSE event schemas (C-48), flags enum (C-15), a path parameter that is not in the template (C-7).
- **Defects that are not visible in the specification.** Springdoc silently takes the first of the same-named schemas (C-31), NestJS overwrites them one by another. Only the recommended backend lint (R15.6) or a manual check catches them. Therefore the documentation (R15.5) should describe how the backend team runs `check` in its CI (R2.4).

## D. Recipes for backends (R15.5): how to get a good specification

### D.1. NestJS (`@nestjs/swagger`)

1. **CLI plugin** (`nest-cli.json`). It sets `required` from `?`, the type and enum from the TS type, `default` from the initializer, constraints from `class-validator`, descriptions from comments. Only the `*.dto.ts`/`*.entity.ts` files are analyzed; other suffixes are configured through `dtoFileNameSuffix` [S35]:
   ```json
   { "compilerOptions": { "plugins": [{ "name": "@nestjs/swagger",
       "options": { "introspectComments": true, "classValidatorShim": true, "autoFillEnumName": true } }] } }
   ```
   `autoFillEnumName` sets `enumName` automatically, so the enum becomes a separate schema rather than being duplicated inline (C-11).
2. **`operationIdFactory`**. By default the id has the form `controllerKey_methodKey_version` [S35]:
   ```ts
   SwaggerModule.createDocument(app, config, {
     operationIdFactory: (controllerKey, methodKey) => methodKey, // uniqueness is up to you
     excludeDynamicDefaults: true,   // defaults such as new Date() do not end up in the document (C-28, C-37)
   });
   ```
3. **Version 3.1 — only with `@nestjs/swagger` ≥12.0.0.** It was in 12.0.0 that nullability began to be written according to the document version. On 11.x a 3.1 document contains `nullable`, and 3.0 contains `oneOf` with `type: 'null'` [S31]. On 11.x stay with 3.0.
4. **Unique schema names:** `@ApiSchema({ name: 'Menu' })`. Otherwise same-named DTOs from different modules overwrite each other (C-31) [S79].
5. **Generics and envelopes:** `@ApiExtraModels(PaginatedDto, Model)` + `allOf: [{ $ref: getSchemaPath(PaginatedDto) }, { properties: { results: { type: 'array', items: { $ref: getSchemaPath(Model) } } } }]`. Exactly this template is what `envelope-detect` will recognize [S35].
6. **Cycles:** a lazy type `@ApiProperty({ type: () => Node })`. **Dictionaries:** `@ApiProperty({ type: 'object', additionalProperties: { $ref: getSchemaPath(X) } })`. **Arrays in a body:** `@ApiBody({ type: [CreateUserDto] })` [S35][S78].
7. **SSE:** there is no built-in decorator. You can use a custom decorator from nestjs/swagger#3728 or an override in the generator [S85].

### D.2. FastAPI / pydantic v2

1. **operationId:**
   ```python
   def custom_generate_unique_id(route: APIRoute) -> str:
       return f"{route.tags[0]}-{route.name}"
   app = FastAPI(generate_unique_id_function=custom_generate_unique_id)
   ```
   Without this, the ids come out in the style of `create_item_items_post` [S42]. The tag prefix is then removed by the R5.1 transformation.
2. **`separate_input_output_schemas=False`** (since 0.102.0) gives one schema instead of `Item-Input`/`Item-Output` [S46]. The alternative is to keep the split and enable `merge-io-variants`.
3. **Do not force `openapi_version="3.0.x"`.** FastAPI generates 3.1 content anyway (`anyOf` with `null`, `const`, `examples`), so the document becomes mixed (C-17) [S39][S42].
4. **Forms through models** (`Annotated[Model, Form()]`, FastAPI ≥0.113.0) instead of separate `Form`/`File` parameters. Then the synthetic `Body_…` schemas do not appear (C-30) [S39].
5. **Unique model names within the application.** Otherwise pydantic gives keys `module__path__Name` with the same `title` (C-31, C-4) [S38][S80].
6. **Discriminated unions:** `Annotated[Cat | Dog, Field(discriminator="pet_type")]`, where `pet_type: Literal["cat"]`. Pydantic will add `discriminator.mapping`, and each variant gets a `const` [S44].
7. **Streams:** `response_class=EventSourceResponse` + return type `AsyncIterable[Item]` (≥0.135.0) or JSON Lines (≥0.134.0). FastAPI generates `itemSchema` itself, and without a type annotation it does not [S32][S34].
8. **Errors:** `responses={404: {"model": ErrorOut}}` for typed 4xx (R11.1). The 422 `HTTPValidationError` is added automatically [S34].

### D.3. Spring Boot / springdoc-openapi

1. Properties [S41]:
   ```properties
   # default since 2.8.0
   springdoc.api-docs.version=openapi_3_1
   # instead of */* (C-38)
   springdoc.default-produces-media-type=application/json
   # deterministic output (C-37)
   springdoc.writer-with-order-by-keys=true
   # or @Schema(name=...) for same-named classes (C-31)
   springdoc.use-fqn=false
   ```
   (In `.properties` a `#` comment works only at the start of a line, so the comments are placed separately.)
2. **Explicit `@Operation(operationId = "...")`**: automatic `_1` suffixes are unstable [S47].
3. **Enum as `$ref`:** `@Schema(enumAsRef = true)` on the enum, or globally `ModelResolver.enumsAsRef = true` [S43].
4. **`Pageable`:** `@ParameterObject Pageable pageable` expands the `page`/`size`/`sort` parameters [S43]. For a stable response shape — `@EnableSpringDataWebSupport(pageSerializationMode = VIA_DTO)`. But in a generic wrapper the `Page<T>` type may collapse to `PageObject` [S49], so it is better to return your own page DTO.
5. **Required / nullable:** `@Schema(requiredMode = Schema.RequiredMode.REQUIRED)`; `@Nullable`. Regressions in 2.8.17–3.1.x (C-19) show that the output must be **pinned with a snapshot test of the specification** in the backend's CI [S45].
6. **Polymorphism:** `@JsonTypeInfo(property = "kind")` + `@JsonSubTypes` **and** `@Schema(discriminatorProperty = "kind", discriminatorMapping = {@DiscriminatorMapping(value = "foo1", schema = Foo1.class)})`. Names from `@JsonSubTypes` do not get into the mapping automatically [S48][S47].
7. **Errors:** `@ApiResponse(responseCode = "400", content = @Content(mediaType = "application/problem+json", schema = @Schema(implementation = ProblemDetail.class)))` [S47].

### D.4. ASP.NET Core

**Microsoft.AspNetCore.OpenApi (.NET 9/10)** [S52]:
1. JSON options for OpenAPI are set **globally**. MVC options (`AddControllers().AddJsonOptions`) do not affect the document: in the MS docs table they have "Influence on OpenAPI: None".
   ```csharp
   builder.Services.Configure<Microsoft.AspNetCore.Http.Json.JsonOptions>(o => {
       o.SerializerOptions.NumberHandling = JsonNumberHandling.Strict;      // integer instead of [integer,string]+pattern (C-23)
       o.SerializerOptions.Converters.Add(new JsonStringEnumConverter());   // enum strings with names (C-12)
   });
   builder.Services.AddOpenApi(o => o.OpenApiVersion = OpenApiSpecVersion.OpenApi3_1);
   ```
2. **operationId:** `.WithName("getUser")` or `[EndpointName("getUser")]`. Without this there is no `operationId` in the document (C-34).
3. **Media types:** `[Produces("application/json")]` / `[Consumes("application/json")]` remove `text/json`, `application/*+json` and `text/plain` (C-39). Errors: `[ProducesResponseType<ProblemDetails>(400, "application/problem+json")]`.
4. **Polymorphism:** `[JsonPolymorphic]` on an **abstract** base type + `[JsonDerivedType(typeof(Bar), "bar")]`. For a concrete base type the discriminator will not end up in the document [S52].
5. **Required:** `[Required]` or the `required` modifier. Decimal: a schema transformer that sets `format: decimal` (C-24).

**Swashbuckle.AspNetCore** (v10) [S50][S51]:
```csharp
builder.Services.AddSwaggerGen(o => {
    o.CustomOperationIds(api => api.TryGetMethodInfo(out var mi) ? mi.Name : null); // C-34
    o.SupportNonNullableReferenceTypes();
    o.NonNullableReferenceTypesAsRequired();
    o.UseAllOfForInheritance();
    o.UseOneOfForPolymorphism();
    o.CustomSchemaIds(t => t.FullName!.Replace('+', '.'));   // collisions; '+' is not allowed in a key (C-32)
});
app.UseSwagger(o => o.OpenApiVersion = OpenApiSpecVersion.OpenApi3_1); // v10+, default 3.0
```
After upgrading to v10, check nullability: the combination of `SupportNonNullableReferenceTypes` + `UseAllOfToExtendReferenceSchemas` gives `type: 'null'` + `allOf` (C-19) [S54]. To rename enum values in System.Text.Json you need `[JsonStringEnumMemberName]` (.NET 9+), because STJ ignores `[EnumMember]` [S51].

### D.5. Recommended backend lint (R15.6): minimal checklist

These codes are worth enabling as **error** in the backend's CI (`check` mode, R2.4):
- SG101–SG103 (`$ref`), SG502 (duplicate `operationId`), SG504/SG505 (path parameters);
- SG001/SG002 (mixed dialects), SG204 (`type: 'null'` + structure);
- SG601 (`*/*`), SG402 (discriminator without mapping), SG507 (name collisions);
- SG701 (unstable output), that is, two generations in a row must give the same document.

As **warning**: SG201, SG202, SG203, SG301, SG303, SG304, SG401, SG604.
